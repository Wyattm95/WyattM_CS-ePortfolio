Artifact Overview

This artifact is a rescue animal management application developed in Java. The application is console-based and allows users to intake new rescue dogs and monkeys, reserve animals, and print lists of dogs, monkeys, or available rescue animals through a menu system. This project was originally developed as a final project while I was enrolled in IT-145: Foundation in Application Development.

Narrative

I included this artifact in my ePortfolio because it gave me the opportunity to demonstrate my ability to enhance an existing Java application by improving its algorithms, data structures, and overall code quality. One weakness in the original application was that animal records were stored in separate ArrayLists, and the program used repeated linear searches to check for duplicate animal records. Improving this weakness allowed me to demonstrate my ability to use a more appropriate data structure by replacing the ArrayLists with HashMaps. In the enhanced version, animal records are stored using a unique key created from the animal type and animal name, which allows the program to check for existing animal records more efficiently.

Another weakness in the original application was that much of the program logic was contained in the Driver class. This class handled menu navigation, user input, animal intake, reservation logic, printing animal lists, and animal record storage. Improving this weakness allowed me to demonstrate my ability to separate application logic into more focused classes, including a Main class, MenuManager class, AnimalManager class, and AnimalValidator class. This made the application easier to read, maintain, and expand.

The enhancement process also allowed me to improve the quality of the animal data stored in the application. In the original version, many values were stored as strings, including age, weight, acquisition date, and monkey measurement values. In the enhanced version, I updated these fields to use more appropriate data types, such as int for age, double for weight and measurements, and LocalDate for acquisition dates. I also improved encapsulation by changing monkey-specific fields from public to private and keeping access controlled through getter and setter methods. These changes made the object structure cleaner and helped prevent inconsistent data from being stored.

The enhancements to this artifact met the course outcomes I originally planned to address, which were Course Outcomes 3 and 4. Course Outcome 3 focuses on designing and evaluating computing solutions using algorithmic principles, appropriate data structures, and an understanding of the trade-offs involved in technical decisions. This outcome was met by replacing repeated ArrayList searches with HashMap-based record storage, demonstrating my ability to evaluate an existing computing solution and improve it using algorithmic principles and a more appropriate data structure. Course Outcome 4 focuses on applying computing techniques, skills, and tools to create solutions that provide value and meet application goals. This outcome was met by applying object-oriented design practices, input validation, improved data types, and better class organization to create a more reliable and maintainable application.

The process of enhancing this artifact showed me how data structure selection affects application design. One challenge I faced was deciding how to move from separate ArrayLists to HashMaps while still preserving the original functionality of the program. The HashMap improved direct lookup operations, such as checking whether an animal already exists, but other operations still required iteration, such as printing all animals or reserving an animal by country. This helped me see that no single data structure improves every part of an application equally. The best choice depends on how the application actually uses and accesses the data.

Another challenge came from changing several fields from strings to more appropriate data types. Updating values such as age to int, weight and monkey measurements to double values, and acquisition date to LocalDate improved the structure and accuracy of the animal records. However, this also created new challenges because the program could crash if the user entered the wrong type of data, such as letters for an age or weight value. To handle this, I added try-catch blocks around the numeric and date conversions so invalid input could be caught before the program continued creating the animal record. If invalid input is entered, the method displays an error message and returns the user to the menu loop without creating the animal object. This demonstrated that improving or changing data types also affects input validation and error handling, which are necessary to keep the application stable.
